# Claims file: how it works

Reference for the `draft` skill. `docs/claims-by-source.md` lists, per source, every claim that `main.md` attributes to it, so the researcher can tick each one off against the source; its last section, "Register of the author's own inferences", is the single register of unsourced inferences, generalisations and hypotheses. The full behaviour of the script is in the docstring of `scripts/claim_quotes.py`.

## Structure

Each source has a `## ` section headed as the source is cited in `main.md`: `## Smith et al. (2023)`, `## Smith & Jones (2023)` or `## Smith (2023)`, optionally followed by more text. Each claim is a numbered checkbox line with a section tag in brackets, `- [ ] (2) [Related Work] ...`. The tag is the start of the `main.md` heading the claim sits in, case-insensitive (`[Intro]` matches "Introduction"; several tags may be separated by commas). The script finds the source's sentences by the first author's surname and the year in the heading, so no table needs editing when a source is added.

## Rewriting from the current text

When the text of `main.md` is stable, rewrite the claims file from scratch from the current text rather than annotating old claims: restate each claim in the current wording, keep a tick only where the claim is unchanged in substance, and leave the history to `wiki/log.md` and git. Then run the script (below) to attach the current sentences under each claim.

## Generated quote lines

The `    - > sentence` lines under each claim are generated by `python -I scripts/claim_quotes.py --write` and never edited by hand; a hand edit is overwritten on the next run. With `--write` the script also puts ✅ in front of a section title once all its top-level boxes are ticked, and removes it when a box is unticked. Without `--write` it is a dry run that prints the `main.md` line number beside each quote; `--only <source>` limits it to the sources whose heading starts so, `--skip <source>` leaves them out, and `--check` prints only whether the file is out of date and the Notes (what the hook runs).

The quote lines carry no line numbers on purpose: a number changes in every quote below an edit whenever a paragraph is split or a heading added, which buries the quotes that really changed. Without it a quote line changes only when its sentence does, so `git diff docs/claims-by-source.md` shows exactly which claims moved.

## Several claims in one section: `{q: <regex>}`

By default a claim is given every sentence under a matching heading that cites the source, so claims sharing a section tag show the same sentences. Where a section holds several claims about one source, end each claim line with `{q: <regex>}` naming a distinctive phrase of its sentence. The regex replaces the citation test rather than narrowing it, so it also reaches a sentence that continues a citation without naming the source ("The same study ..."), which is otherwise not found at all. Two claims may share a sentence. The script reports a regex that matches nothing, and a sentence citing the source that no claim lists once any claim of that section is narrowed. Two sources with the same first-author surname and year match each other's sentences; narrow their claims the same way.

## Read the Notes after every run

Both failure modes produce nothing rather than an error: a claim whose tag no longer matches a heading (after a section was renamed) and a source whose citations no longer match its heading (cited differently from how the heading names it) collect no quotes, which shows up only in the Notes. After a structural edit of `main.md`, run the script without `--write` first, read the Notes, then write.

## Register of the author's own inferences

The last section is the only record of the statements in `main.md` that no single source supports: generalisations from one or two studies, reasoned steps beyond what any source says, and the author's hypotheses. `main.md` does not mark them in the text, so every new one needs an item. Each item gives the wording in `main.md` (a **Text:** line), the sources it builds on and a **Support** value: `sourced`, `thin`, `inference`, `opinion`, `none` or `inherited`. The reading guide at the top of that section defines what each value claims and how it fails, and is the authority. Do not invent a seventh value: add it to the guide and to `SUPPORT_VALUES` in `scripts/check.py` together; `check.py` warns about an unknown or missing value.

The register quotes `main.md` by hand in its **Text:** lines, and `claim_quotes.py` reports a quoted wording that `main.md` no longer contains. When a wording changes, update the quote and keep the old wording in parentheses, which the check skips as history.
